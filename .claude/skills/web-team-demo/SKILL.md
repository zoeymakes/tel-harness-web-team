# 하네스 웹팀 — 경량 모드 (시연용)

`web-team`과 **같은 팀·같은 구조**를 쓰되, 시연 시간에 맞춰 범위와 검수를 줄인 모드입니다.
목표 소요: **12~15분**. 정식 모드는 60~140분이며, 품질 게이트가 다릅니다.

> **이 모드로 만든 결과물은 정식 결과물이 아닙니다.** 최종 보고에 반드시 그 사실과 생략한 게이트를 명시하세요.

## 정식 모드와의 차이 (사용자에게 먼저 1줄로 알릴 것)

| | 정식 `web-team` | 경량 `web-team-demo` |
| --- | --- | --- |
| 분석 | 6명 병렬 | **3명 병렬** (planner · design · data) |
| 산출 범위 | 전 흐름 + 상태 6종 | **검색 → 필터 → 카드 → 상세**까지 (예약 흐름 제외) |
| 데이터 | 8건 | **4건** |
| 이미지 | 매번 다운로드·선별 | **기존 `site/assets/` 재사용** |
| 검수 | 기능+비주얼 각 최대 3라운드 | **1라운드, 스팟 체크** |
| 수정 루프 | 최대 2회 | **최대 1회** |

## 시간 예산 (초과하면 그 단계를 잘라내고 보고)

```txt
0단계 브리프          0.5분   기존 브리프 재사용 우선
1단계 분석 3명 병렬     3분
2단계 지시서           1분
3단계 구현             6분
4단계 이중 검수(병렬)   4분
5단계 보고            0.5분
─────────────────────────
합계                 약 15분
```

---

## 0단계 — 브리프 (오케스트레이터, 30초)

- `references/briefs/`에 요청과 맞는 브리프가 **있으면 그대로 재사용**하고 새로 쓰지 않습니다. (시연에서 가장 큰 시간 절약)
- 없으면 **10줄 이내 미니 브리프**만 씁니다: 목적 / 주 사용자 / 핵심 흐름 1줄 / 포함 4~5개 / 제외(결제·로그인·지도·서버) / 디자인은 `references/design-system.md` 기본.
- `site/assets/`에 이미지가 있으면 **그대로 재사용**한다고 명시합니다. 없으면 이미지 4장만 받도록 지시합니다.

## 1단계 — 분석 3명 병렬 (3분)

`business-researcher` · `ux-designer` · `copywriter`는 **호출하지 않습니다.** 그 관점은 브리프와 기존 문구·레퍼런스로 대체하고, 생략 사실을 최종 보고에 적습니다.

| 에이전트 | 받아올 것 |
| --- | --- |
| `product-planner` | Must 6개 이내 + 각 완료 기준 1줄. Should·리스크 분석 생략 |
| `design-system-specialist` | 토큰 + 구성 명세 + 이미지 방향 3종 — **각 15줄 이내** |
| `data-backend-architect` | 4건 스키마 + 코드값 매핑 + 가격 계산식. 샘플 값 예시 1건만 |

**모든 위임 프롬프트에 아래 문구를 그대로 넣으세요:**

```txt
## 경량 모드 제약 (반드시 지킬 것)
- 시연용 경량 실행입니다. 산출물은 표 중심으로 40줄 이내로 쓰세요.
- 대안 비교·리스크 분석·확인 질문 목록을 길게 쓰지 마세요. 결론만 주세요.
- 파일 탐색은 브리프와 지정된 레퍼런스 1개로 제한하고, 저장소 전체를 훑지 마세요.
```

## 2단계 — 지시서 (1분)

정식 모드의 6장 구성을 **3장으로 압축**합니다:
1. 구현 항목 (완료 기준 포함, 8개 이내)
2. 데이터 스키마 + 토큰 (에이전트 산출 그대로 인용, 재작성 금지)
3. **시각 목표 3개** + 하지 말 것 5개

**시각 목표는 경량 모드에서도 생략하지 않습니다.** 최소 3개:
- 데스크톱 1440×900 첫 화면에 카드 이미지 첫 줄이 보인다
- 모든 이미지 자리가 실제 사진이다 (단색·그라디언트 사각형 금지)
- 필터는 얇은 칩 스트립이다 (보더 박스 패널 금지)

## 3단계 — 구현 (frontend-builder, 6분)

위임 프롬프트에 아래를 **반드시** 포함하세요:

```txt
## 경량 모드 제약 (반드시 지킬 것)
- 시연용 경량 실행입니다. 목표 소요 6분.
- `site/assets/`의 기존 이미지를 재사용하세요. 새로 다운로드하지 마세요.
  (없을 때만 4장 받고, 실패하면 https://picsum.photos/seed/<이름>/1200/900 로 즉시 대체)
- 셀프 스크린샷은 **데스크톱 1회만** 찍고 봅니다. 촬영→수정→재촬영 루프를 반복하지 마세요.
  명백한 깨짐만 고치고, 미세 조정은 QA에 맡기세요.
- CDP 계측·전수 측정을 하지 마세요. 눈으로 보고 판단하세요.
- 예약 폼·예약 확인 화면은 만들지 않습니다. 상세 패널까지가 범위입니다.
```

## 4단계 — 이중 검수 1라운드 (병렬, 4분)

`qa-reviewer`와 `visual-qa`를 **한 메시지에서 병렬 호출**하되, 두 프롬프트에 아래를 넣습니다:

```txt
## 경량 모드 제약 (반드시 지킬 것)
- 시연용 경량 검수입니다. 목표 소요 4분.
- **전수 검사 금지.** 아래 핵심 항목만 스팟 체크하고, 나머지는 "미검사"로 명시하세요.
- 발견은 심각도 [상]·[중]만 보고하세요. [하]는 "잔여 이슈"에 한 줄로만.
- CDP 전수 계측·문구 80개 대조 같은 정밀 검증은 하지 마세요.
```

- `qa-reviewer` 스팟 체크 항목: ① 콘솔 에러 0 ② 필터 `data-*` ↔ 코드값 일치 ③ 0건 상태 동작 ④ 링크·선택자 깨짐 없음 ⑤ label 연결
- `visual-qa` 스팟 체크 항목: ① 첫 화면에 카드 보임 ② 이미지가 실사진 ③ 필터가 칩 스트립 ④ 겹침·잘림 없음

**수정 루프는 최대 1회.** [상] 항목만 고치고, 남는 건 전부 "남은 확인 질문"으로 보고합니다.

## 5단계 — 보고 (30초)

```txt
완료 (경량 모드):
- 소요 시간:
- 브리프: (재사용/신규)
- 바꾼 파일:
- 가동한 에이전트: (3+2명, 생략한 3명 명시)
- 실행한 검사: (check_repo, 기능 QA, 비주얼 QA — 스팟 체크 범위)
- 경량 모드에서 생략한 것: (분석 3명 / 예약 흐름 / 검수 라운드 / 전수 검증)
- 남은 확인 질문:
```

**반드시 한 줄 덧붙일 것**: "정식 품질이 필요하면 `/web-team`으로 다시 돌려야 합니다."

## 금지 사항

- 시각 목표 3개를 생략하는 것 (경량이어도 이건 유지)
- 두 QA 중 하나를 건너뛰는 것 (라운드를 줄이는 것과 다름)
- 경량 모드 결과를 정식 결과처럼 보고하는 것
- 시간을 아끼려고 서브에이전트 없이 오케스트레이터가 직접 구현하는 것 — **팀 구조를 보여주는 게 이 모드의 목적입니다**
