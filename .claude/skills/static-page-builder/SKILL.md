# Static Page Builder

브리프에 정의된 페이지를 `site/index.html`, `site/styles.css`, `site/app.js`와 `site/assets/`(생성 SVG) 안에서 구현하기 위한 명세입니다. 정적 HTML/CSS/JS만 사용하고, `open site/index.html`만으로 동작해야 합니다. 페이지의 구체 구성(어떤 입력, 어떤 카드, 어떤 필터)은 브리프와 작업 지시서가 정하고, 이 스킬은 구현 패턴과 품질 기준을 정합니다.

## 첫 화면 원칙 (최우선)

- 데스크톱 첫 뷰포트(1440×900)에서 **콘텐츠 카드의 첫 줄이 보여야 합니다.** 상단바 + 검색/입력 + 필터 스트립을 다 합쳐도 첫 화면 세로의 절반을 넘기지 않습니다.
- 필터는 콘텐츠 위의 **얇은 가로 스트립(칩/pill)**으로 둡니다. 보더 박스로 감싼 큰 필터 패널이 카드를 화면 밖으로 밀어내는 구성은 금지입니다.
- 페이지의 시각적 무게는 이미지가 담당합니다. 텍스트·보더가 화면을 지배하면 레이아웃을 다시 잡습니다.

## 페이지 기본 구성 (위에서 아래 순서)

1. 상단 바: 서비스명 + mock demo 배지
2. 검색/핵심 행동 영역: 한 줄 가치 제안 + 입력 (콤팩트하게 — 첫 화면을 잠식하지 않게)
3. 필터/카테고리 스트립 (얇은 1줄, 목록형 페이지일 때)
4. 결과 요약 (aria-live, 한 줄)
5. 카드/목록 그리드 — **첫 줄이 첫 화면에 걸리도록**
6. 푸터: mock demo 고지

## 이미지 에셋 (site/assets/)

사진 자리는 실제 이미지로 채웁니다. **단색/그라디언트 사각형·이모지 채움은 visual-qa 즉시 실패 조건입니다.**

### 1순위 — 무료 라이선스 실사진 다운로드 (기본 경로)

빌드 시점에 받아서 로컬 파일로 저장합니다. 런타임 핫링크(외부 URL 참조)는 금지입니다.

```bash
curl -L --max-time 30 -o site/assets/stay-01.jpg "<무료 라이선스 사진 URL>"
file site/assets/stay-01.jpg          # → JPEG/PNG 여야 함 (HTML이면 404 응답)
stat -f%z site/assets/stay-01.jpg     # → 20000 초과여야 함
```

- 소스: Unsplash·Pexels 등 무료 라이선스만. 각 파일의 원본 URL을 `site/assets/credits.txt`에 기록합니다.
- 피사체는 아트 디렉션의 장면 목록에 맞춥니다(항목마다 다른 사진 — 같은 사진 복붙 금지). 톤이 어긋난 사진 하나가 그리드 전체를 싸구려로 만듭니다.
- 검증 실패(404·깨짐)는 다른 URL로 재시도 → 최후 수단은 시드 고정 소스(`https://picsum.photos/seed/<이름>/1200/900`).
- 용량: 카드용은 긴 변 1200px 내외면 충분합니다(`?w=1200&q=80` 등 리사이즈 파라미터 활용).

### 2순위 — 레이어드 SVG 일러스트 (네트워크 불가 시 폴백)

- **레이어 구조 (각 이미지 필수)**: ① 배경(하늘·벽, 그라디언트 허용) ② 중경(지형·수평선·가구) ③ 주 피사체(건물·실내·핵심 사물) ④ 디테일 6개 이상(창문 불빛, 문, 지붕, 소품, 그림자) ⑤ 전경(식물·난간·커튼 등)
- **스타일 통일**: 전 이미지가 같은 일러스트 문법(플랫/듀오톤 등). 항목마다 장면·시간대·구도·팔레트를 변주해 서로 구분되게.
- **품질 하한**: 요소 20개 이상, `<defs>` 그라디언트·간단한 패턴 활용 권장. 외부 href 금지.

### 공통

- 한 페이지에서 사진과 일러스트를 **혼용하지 않습니다** (전부 사진 또는 전부 일러스트).
- **비율**: 카드 4:3 또는 1:1(레퍼런스 컴포넌트 스펙 따름), 히어로는 와이드. CSS `aspect-ratio` + `object-fit: cover`로 고정합니다.
- **참조**: `<img src="./assets/이름.jpg" alt="장면 설명">` (장식이면 `alt=""` + `aria-hidden`)
- 아트 디렉션(무드·장면 목록)은 작업 지시서의 이미지 방향을 따릅니다.

## 섹션별 구현 패턴

### 핵심 행동 영역 (폼)
- 입력은 2~4개로 제한하고, 순서는 사용자의 사고 순서를 따른다.
- 모든 입력에 `<label>` 필수. placeholder를 label 대용으로 쓰지 않는다.
- 제출 버튼 문구는 결과를 예고한다. ("검색" ❌ → "예약 가능 숙소 보기" ⭕)
- 제출 시: 페이지 이동 없이(preventDefault) 결과 요약과 목록을 갱신한다.

### 필터
- 종류는 3~5개로 제한(전체 + 유형·카테고리). 얇은 스트립 한 줄에 들어가는지 확인.
- 각 필터 버튼의 `data-*` 값은 mock 데이터의 코드값과 정확히 일치해야 한다. (불일치 = 0건 버그)
- 선택 상태는 색뿐 아니라 배경 반전 등 형태로도 구분한다.

### 결과 요약
- 사용자의 입력값을 되풀이해 신뢰를 준다: "{조건} · {조건}에 맞는 {항목} {n}개"
- `aria-live="polite"` 유지. 필터/제출 때마다 갱신한다.

### 카드
정보 순서를 모든 카드에서 동일하게 유지한다:
1. 이미지 영역 — `assets/`의 SVG 일러스트, 카드 높이의 절반 이상을 차지 (사진 우선 레퍼런스일 때)
2. 항목명 (h2 또는 h3)
3. 핵심 정보 (위치·특징·조건 등 브리프의 비교 축)
4. 평가 + 근거 개수 (개수 없는 평점 금지)
5. 태그 (최대 3개)
6. 가격/수치 (굵게, 단위 포함, 숫자는 `toLocaleString`으로 포맷)
7. CTA 버튼

### CTA 상태
- 가능/기본 상태: primary 채움 버튼, 행동을 예고하는 문구
- 불가/품절/마감 상태: 보조 스타일 버튼, 막다른 길 금지 — "날짜 바꾸기" 같은 대안 행동 문구

### 빈 상태 (필수)
- 필터/검색 결과 0건이면 빈 그리드 대신 안내 블록을 렌더한다: 상황 설명 1줄 + "조건 다시 선택" 행동 버튼(전체 필터로 리셋).

## mock data 규칙

스키마 상세는 `mock-data-modeling` 스킬을 따른다. 최소 규칙:
- 데이터 배열과 표시명 매핑은 `app.js` 상단, 렌더 함수는 하단
- 가격·평점은 숫자 타입, 상태 여부는 불리언
- 각 레코드에 이미지 파일명 필드를 두고 `assets/` 파일과 1:1 대응시킨다
- 레코드는 4~8개면 충분. 필터 축(유형·가격·상태)이 서로 다른 조합으로 구성해 필터 데모가 되게 한다.

## 완료 기준 (Definition of Done)

- [ ] `open site/index.html`로 열었을 때 브리프의 핵심 흐름이 처음부터 끝까지 보인다
- [ ] **데스크톱 첫 화면(1440×900)에 카드 이미지 첫 줄이 보인다** (셀프 스크린샷으로 확인)
- [ ] **모든 이미지 자리가 실제 이미지다**(검증된 실사진 또는 레이어드 SVG 장면) — 단색/그라디언트 사각형·이모지·깨진 파일 없음, 사진이면 `assets/credits.txt` 존재
- [ ] 이미지들이 같은 스타일이면서 서로 다른 장면이다
- [ ] 모든 필터 버튼이 실제로 목록을 바꾼다 (0건 포함)
- [ ] 0건 상태에서 대안 행동이 제시된다
- [ ] 모바일에서 입력 영역 세로 배치, 카드 1열, 겹침·가로 스크롤 없음
- [ ] JS를 꺼도(noscript) 안내 문구가 보인다
- [ ] mock demo 고지가 화면에 있다
- [ ] `python3 scripts/check_repo.py` 통과
