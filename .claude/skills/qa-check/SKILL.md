# QA Check

구현된 `site/` 페이지를 검수하는 체크리스트입니다. 각 항목은 **확인 방법**대로 직접 확인하고, 확인하지 않은 항목을 통과로 기록하지 않습니다.

## 1. 자동 검사

- `python3 scripts/check_repo.py` 실행 → 출력을 결과에 그대로 기록

## 2. 요구사항 대조

- 이번 작업의 요구사항 목록(없으면 해당 브리프 `references/briefs/*.md`의 MVP 포함 목록)을 기준으로, 항목마다 구현 위치를 파일:줄로 찾는다. 못 찾으면 "누락".

## 3. 참조 무결성

| 항목 | 확인 방법 |
| --- | --- |
| CSS/JS 경로 | `index.html`에 `./styles.css`, `./app.js` 참조 존재 + 파일 존재 |
| DOM 선택자 | `app.js`의 `querySelector` 대상 id/class가 HTML에 존재 |
| 필터-데이터 정합 | 필터·탭 버튼 `data-*` 값 == 데이터 코드값 (불일치 = 0건 버그) |
| 죽은 링크 | `href="#"` 또는 존재하지 않는 anchor 확인 |

## 4. 접근성 기본

| 항목 | 확인 방법 |
| --- | --- |
| 폼 label | 모든 input/select가 `<label>`로 감싸이거나 연결됨 |
| 버튼 텍스트 | 모든 버튼에 읽을 수 있는 텍스트 (아이콘/이모지 단독 ❌) |
| 장식 요소 | 이모지·장식 블록에 `aria-hidden="true"` |
| 동적 영역 | 결과 요약에 `aria-live` |
| JS 실패 대비 | `<noscript>` 안내 존재 |
| 언어 | `<html lang="ko">` |

## 5. 반응형

- `styles.css`에 모바일 미디어 쿼리 존재
- 그 안에서: 입력 영역 세로 배치, 카드 그리드 1열
- 버튼 `min-height` 44px 이상 (터치 타겟)

## 6. 상태 처리

- 필터·검색 결과 0건일 때 빈 상태 UI(안내 + 대안 행동)가 렌더되는가 (코드 흐름으로 확인)
- 불가/품절 항목의 CTA가 가능 항목과 문구·스타일로 구분되는가

## 7. 문구 기준

- 금지어 grep: "최고의", "혁신적인", "완벽한", "새로운 경험" → 0건이어야 함
- mock demo 고지 문구가 화면에 존재

## 결과 형식

```txt
판정: 통과 | 수정 필요

통과:
- 항목 — 확인 방법

수정 필요:
- [상|중|하] 항목 — 위치(파일:줄) — 기대 동작

미검사 항목과 사유:
- (없으면 "없음")
```
