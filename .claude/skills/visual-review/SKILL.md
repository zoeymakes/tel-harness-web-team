# Visual Review

코드가 아니라 **렌더된 화면**을 검수하는 절차입니다. 원칙: 스크린샷을 찍고, 반드시 Read로 직접 본 뒤, 관찰한 사실로만 판정합니다.

## 1. 스크린샷 촬영

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
# 없으면 순서대로 시도: Chromium(/Applications/Chromium.app/...), Edge, `which chromium chrome google-chrome`
OUT=$(mktemp -d)
URL="file://$PWD/site/index.html"

"$CHROME" --headless --disable-gpu --hide-scrollbars \
  --window-size=1440,900  --screenshot="$OUT/desktop-fold.png" "$URL"   # 데스크톱 첫 화면
"$CHROME" --headless --disable-gpu --hide-scrollbars \
  --window-size=1440,2800 --screenshot="$OUT/desktop-full.png" "$URL"   # 데스크톱 전체 흐름
"$CHROME" --headless --disable-gpu --hide-scrollbars \
  --window-size=390,844   --screenshot="$OUT/mobile.png" "$URL"         # 모바일
```

- 결과 PNG가 새하얗거나 수 KB뿐이면 file:// 로딩 실패입니다. `python3 -m http.server <포트>`를 `site/`에서 백그라운드로 띄우고 `http://127.0.0.1:<포트>/index.html`로 재시도한 뒤 서버를 종료합니다.
- 브라우저 실행이 아예 불가능한 환경이면 촬영을 생략하되, **판정을 "통과"로 내지 말고** "미검사 — 스크린샷 불가"로 보고합니다.
- 인터랙션 이후 상태(모달 열림 등)가 필요하면: node + CDP(`--remote-debugging-port`)로 클릭 후 캡처하거나, 불가하면 미검사로 명시합니다.

## 2. 반드시 Read로 볼 것

찍은 PNG를 **하나씩 Read 도구로 열어** 실제로 봅니다. 파일 크기나 촬영 성공 여부만 확인하고 넘어가는 것은 검수가 아닙니다.

## 3. 판정 체크리스트

각 항목을 스크린샷에서 관찰한 사실과 함께 판정합니다.

### A. 첫 화면 구성 (desktop-fold.png) — 최우선
- [ ] 스크롤 0에서 **콘텐츠(카드 이미지) 첫 줄이 보인다**. 검색·필터·안내만 보이면 실패.
- [ ] 컨트롤 영역(검색 폼 + 필터)이 첫 화면 세로의 절반을 넘지 않는다.
- [ ] 필터가 얇은 가로 스트립(칩/pill)이다. 보더 박스로 감싼 큰 필터 패널이 콘텐츠를 밀어내면 실패.
- [ ] 이미지가 첫 화면 면적의 상당 부분(대략 40% 이상)을 차지한다 — 사진/일러스트 중심 레퍼런스일 때.

### B. 이미지 품질 — 즉시 실패 조건 포함
- [ ] 이미지 자리가 **실제 장면(사진 또는 일러스트)**이다. 단색/그라디언트 사각형·이모지 채움이면 **즉시 실패**. 깨진 이미지 아이콘(다운로드 실패 흔적)도 실패.
- [ ] 카드마다 이미지가 서로 구분된다(같은 그림 복붙 아님).
- [ ] 이미지들의 톤·스타일이 통일되어 한 서비스의 아트 디렉션으로 보인다. 사진과 일러스트가 한 화면에 섞여 있으면 실패.

### C. 밀도·정렬·리듬 (desktop-full.png)
- [ ] 카드 그리드가 정렬되어 있고, 레퍼런스의 열 수 기준(예: 데스크톱 4열+)을 만족한다.
- [ ] 섹션 간 여백이 일정한 리듬이다. 어색하게 빈 공간이나 뭉친 구간이 없다.
- [ ] 카드 안 정보 블록의 높이·순서가 카드끼리 나란히 맞는다.

### D. 위계·색
- [ ] 눈이 가는 순서가 콘텐츠 → 주 CTA → 보조 순이다.
- [ ] 주 강조색이 남용되지 않았고(화면당 주 CTA 중심), 반대로 화면이 무채색뿐이어서 죽어 보이지도 않는다.
- [ ] 텍스트가 이미지·배경 위에서 읽힌다.

### E. 레퍼런스 유사성 판정 — 최종 관문
- `references/design-system.md`의 Overview·Composition 서술을 옆에 놓고: **"이 문서가 묘사하는 서비스의 실제 스크린샷이라고 믿을 수 있는가?"**
- 아니라면, 무엇이 다른지 구체적으로 나열한다. (예: "레퍼런스는 사진이 시각 무게를 담당한다고 했지만 스크린샷은 텍스트와 보더가 화면을 지배한다")

### F. 모바일 (mobile.png)
- [ ] 겹침·가로 스크롤·잘린 요소가 없다.
- [ ] 첫 화면에 핵심 행동(검색 등)이 보이고, 카드가 지나치게 밀리지 않았다.

## 4. 결과 형식

```txt
판정: 통과 | 수정 필요

찍은 스크린샷: (경로 — 뷰포트별)
첫인상 판정: (E 항목 답 1~2줄)

항목별:
- [통과|실패] A-1 … — 관찰: (스크린샷에서 본 것)

수정 필요:
- [상|중|하] 현상 — 위치(스크린샷/화면 영역) → 교정 지시(달성 기준 포함)

미검사 항목과 사유: (없으면 "없음")
```

## 원칙

- 판정 근거는 항상 "스크린샷에서 관찰한 사실"이다. 코드 추정으로 시각 판정을 대신하지 않는다.
- 규칙 준수와 좋아 보임은 다르다. 체크리스트를 다 통과해도 E에서 "믿기 어렵다"면 수정 필요다.
- 교정 지시는 실행 가능해야 한다: 무엇을(대상), 어떻게(방법), 언제 끝나는지(관찰 가능한 달성 기준).
