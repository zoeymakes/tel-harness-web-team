# Travel Page Builder

숙소 검색/예약형 페이지를 `starter/index.html`, `starter/styles.css`, `starter/app.js` 세 파일 안에서 구현하기 위한 명세입니다. 정적 HTML/CSS/JS만 사용하고, `open starter/index.html`만으로 동작해야 합니다.

## 페이지 구성 (위에서 아래 순서 고정)

1. 상단 바: 서비스명 + mock demo 배지
2. 히어로: 한 줄 가치 제안 + 검색 카드
3. 필터 바
4. 결과 요약 (aria-live)
5. 숙소 카드 그리드
6. 푸터: mock demo 고지

## 섹션별 명세

### 검색 영역
- 입력은 세 가지로 제한: 지역(text, placeholder에 예시 지역), 체크인(date), 인원(select)
- 모든 입력에 `<label>` 필수. placeholder를 label 대용으로 쓰지 않는다.
- 제출 버튼 문구는 결과를 예고: "예약 가능 숙소 보기"
- 제출 시: 페이지 이동 없이(preventDefault) 결과 요약과 카드 목록을 갱신한다.

### 필터
- 종류는 3~5개로 제한(전체 + 숙소 유형). 가격대·편의시설 필터를 추가할 땐 한 줄에 들어가는지 확인.
- 각 필터 버튼의 `data-type` 값은 mock 데이터의 `type` 코드값과 정확히 일치해야 한다. (불일치 = 0건 버그)
- 선택 상태는 색뿐 아니라 배경 반전 등 형태로도 구분한다.

### 결과 요약
- 형식: "{지역} · {인원} 조건에 맞는 숙소 {n}개" — 사용자의 입력값을 되풀이해 신뢰를 준다.
- `aria-live="polite"` 유지. 필터/검색 때마다 갱신한다.

### 숙소 카드
정보 순서를 모든 카드에서 동일하게 유지한다:
1. 이미지 영역 (그라디언트 + 이모지 placeholder, `aria-hidden="true"`)
2. 숙소명 (h2 또는 h3)
3. 위치·핵심 특징 (거리, 침실 수 등)
4. 평점 + 후기 수 (후기 수 없는 평점 금지)
5. 태그 (최대 3개)
6. 가격 (굵게, "1박 {n}원" 형식, 숫자는 `toLocaleString`으로 포맷)
7. CTA 버튼

### CTA 상태
- 예약 가능: primary 채움 버튼, "예약 가능"
- 예약 불가: 보조 스타일 버튼, 막다른 길 금지 — "날짜 바꾸기" 같은 대안 행동 문구

### 빈 상태 (필수)
- 필터/검색 결과 0건이면 빈 그리드 대신 안내 블록을 렌더한다: 상황 설명 1줄 + "조건 다시 선택" 행동 버튼(전체 필터로 리셋).

## mock data 규칙

스키마 상세는 `mock-data-modeling` 스킬을 따른다. 최소 규칙:
- 데이터 배열과 표시명 매핑은 `app.js` 상단, 렌더 함수는 하단
- 가격·평점은 숫자 타입, 예약 가능 여부는 불리언
- 레코드는 3~6개면 충분. 지역·유형·가격·가능 여부가 서로 다른 조합으로 구성해 필터 데모가 되게 한다.
