# Travel Booking Product Brief

> 범용 웹팀 하네스의 **예시 브리프**입니다. 새 프로젝트를 시작하면 오케스트레이터가
> 이 형식(제품 상황 → 핵심 흐름 → 사용자 불안 → 포함/제외)으로 새 브리프를
> `references/briefs/`에 생성합니다.

## 제품 상황

사용자는 여행 날짜와 인원을 정한 뒤, 숙소를 빠르게 비교하고 예약 가능 여부를 확인하고 싶어 합니다.

- **주 사용자**: 여행 일정이 이미 정해진 예비 여행객
- **페이지의 목적**: 조건 입력 → 비교 → 예약 결정까지 한 화면에서 끊기지 않게 한다

## 핵심 사용자 흐름

검색(지역·날짜·인원) → 결과 요약 → 필터 → 숙소 카드 비교 → 예약 CTA

## 사용자 불안

- 실제로 예약 가능한 숙소인지 모르겠다.
- 최종 가격이 얼마인지 헷갈린다.
- 위치가 여행 목적과 맞는지 판단하기 어렵다.
- 후기와 편의시설을 한눈에 비교하기 어렵다.

## 이번 MVP에 포함할 것

- 지역, 날짜, 인원 검색 영역
- 숙소 카드 리스트 — 카드마다 `site/assets/`의 생성 일러스트(사진 자리)
- 가격대/숙소 유형/편의시설 필터
- 예약 가능 여부 CTA
- mock data 기반 카드 렌더링

## 이번 MVP에서 제외할 것

- 실제 결제
- 실제 로그인
- 실제 지도 API
- 실제 DB(Supabase) 연결
- 외부 이미지 API·CDN·외부 URL (※ 팀이 직접 생성하는 `site/assets/` 로컬 이미지는 제외 대상이 아니라 **필수 산출물**입니다)

## 디자인 방향 (선택)

`references/design-system.md`의 토큰·구성 기준을 그대로 사용합니다. (흰 캔버스 + 단일 브랜드 컬러, 사진 우선 카드 — Composition 섹션의 첫 화면 기준 포함)

## 이미지 방향 (선택)

사진 자리는 무료 라이선스 실사진(빌드 시 다운로드 → `site/assets/`, 출처 기록)으로 채웁니다. 톤을 통일하고 숙소마다 장면(해변 독채, 도시 아파트, 숲속 오두막 등)을 변주합니다. 네트워크 불가 시에만 레이어드 SVG 일러스트로 폴백합니다. 상세는 design-system-specialist의 아트 디렉션을 따릅니다.

## 데이터 방향 (선택)

핵심 엔티티는 `stays`(숙소). 유형(house/hotel/pension)·편의시설은 코드값으로 저장하고 표시명 매핑을 분리합니다.
