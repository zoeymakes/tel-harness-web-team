# Consumer Copy Principles — 기본 문구 기준

소비자용 페이지 문구의 기본 기준입니다. 토스 UX 라이팅 가이드에서 웹페이지 문구에 적용 가능한 부분을 발췌·정리했습니다.
브리프에 별도 "카피 방향"(예: 격식체, 전문가 대상 톤)이 있으면 그쪽이 우선합니다.

> 원문 가이드의 미니앱 브랜딩(로고·컬러 설정), 내비게이션/탭바 컴포넌트, 그래픽 리소스, 해상도 설계 항목은
> 이 하네스의 범위(정적 웹페이지 문구)와 무관해 제외했습니다. 디자인 기준은 `references/design-system.md`를 따릅니다.

## 말투 (보이스톤)

**1. 해요체** — 화면의 모든 문구는 상황·맥락을 불문하고 해요체로 통일합니다.

**2. 능동적 말하기** — 최대한 능동형 문장을 씁니다.
- "됐어요" → "했어요"
- '~었' 빼기: "완료되었어요" → "완료했어요"
- 수동형 동사는 능동형으로 바꿔 씁니다.

**3. 긍정적 말하기** — 부정적 커뮤니케이션을 줄이고 긍정형으로 씁니다.
- "안 돼요", "없어요" → "~하면 할 수 있어요"
- 에러·빈 상태 메시지도 "무엇을 하면 되는지" 해결책 중심으로 씁니다.
- 일부 조건만 안 될 때 전체가 안 되는 것처럼 읽히지 않게 씁니다. (사용자는 문장을 스캔합니다)

**4. 캐주얼한 경어** — '~시겠어요?', '~시나요?', '계시다', '여쭈다', '께' 같은 과도한 경어를 쓰지 않습니다.
- "확인하시겠어요?" → "확인할까요?" / "계시다" → "있다" / "여쭈다" → "묻다" / "께" → "에게"
- '~시'를 뺐을 때 문장이 어색하면, 파악하려는 정보를 주어로 삼아 문장을 새로 씁니다.

**5. '{명사}+{명사}' 쓰지 않기** — 한자어 명사 나열은 동사로 풀어 씁니다. ("잔액 부족" → "잔액이 부족해서")

**6. 표기** — '되어요'는 모두 '돼요'로 통일합니다.

## 예외 (허용 사례)

- **수동형 허용**: 서비스 종료·기간 만료(주어 강조), 사용자에게 미치는 영향 안내(연체·해지·적용 — 인과관계 명확화), 민감한 정보 수집 안내(안심).
- **경어('~시나요?') 허용**: 사용자의 맥락을 활용한 질문, 토스에 정보가 없어 사용자가 직접 판단해야 하는 상황, 설문처럼 선의를 기대하는 요청.
- **부정형 허용**: 정책상 서비스를 쓸 수 없을 때, 일부 기능만 쓸 수 없을 때 — 이유를 반드시 함께 안내합니다.

## 버튼·CTA 규칙

- **버튼만 보고 다음 행동을 예측할 수 있어야 합니다.** 화면에서 설명한 가치를 버튼에 반복하지 않고, 누르면 일어나는 일을 동사로 씁니다. "확인", "검색", "더보기", "클릭" 단독 사용 금지.
- CTA 위에 과장되거나 중복된 보조 설명을 얹지 않습니다. 버튼의 역할이 흐려집니다.
- **막다른 길 금지.** 사용자가 거절하거나 빠져나갈 선택지를 항상 남깁니다. (예: 예약 마감 카드에도 "다른 날짜 보기" 같은 대안 행동)
- 다이얼로그의 왼쪽(보조) 버튼 문구는 "닫기"로 통일합니다. "취소"는 진행 중인 작업이 취소된다고 오해할 수 있어 쓰지 않습니다.
- 같은 행동은 화면 어디서든 같은 문구를 씁니다.

예시 (도메인별로 브리프에 맞게 새로 씁니다):
- 숙소 예약: "예약 가능 숙소 보기", "조건 다시 선택", "날짜 바꾸기"
- 커머스: "장바구니에 담기", "재고 있는 상품만 보기"

## 정보 문구 규칙

- 혜택·조건은 숫자와 함께 씁니다. ("저렴한 가격" ❌ → "1박 98,000원" ⭕)
- 불확실한 내용은 확정처럼 말하지 않습니다. mock demo 고지는 정직하게 유지합니다.
- 시스템 메시지(결과 요약 등)는 사용자의 입력 조건을 되풀이해 신뢰를 줍니다.

## 피해야 할 표현

- 과장·빈말: 최고의 / 혁신적인 / 완벽한 / 특별한 / 새로운 경험 / (근거 없는) 프리미엄
- 번역투: "~을 경험하세요", "~을 만나보세요", "~가 제공됩니다"
- 명사 나열로 끝나는 슬로건 ("완벽한 휴식을 위한 프리미엄 스테이")
- 애원·호소·불안 조성으로 행동을 유도하는 표현 (다크패턴)
